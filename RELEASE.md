# Releases

How a version of the modules of this repository is released, and the release protocol of
each version. The protocol names results, never amounts or other data of a real
business.

## Release process

1. **Code on `19.0`:** all changes merged, version `19.0.x.y.z` in the manifests,
   `readme/HISTORY.md` of every changed module updated, README files regenerated by
   pre-commit.
2. **Checks in a fresh database** (the three modules and `l10n_de_euer` from
   [BM1-de/odoo-l10n-germany-euer](https://github.com/BM1-de/odoo-l10n-germany-euer),
   local docker compose setup):
   - `_dev/werkzeuge/test_protocol.sh -d <new database>` runs every test with coverage
     of lines and branches and writes `junit.xml`, `coverage.xml`, `coverage-html/`,
     `test.log` and `summary.md` (tag, commit, Odoo version and image, PostgreSQL
     version, counts and coverage per module and in total; a failed `setUpClass` counts
     for its module). The summary is written by `_dev/werkzeuge/protocol_summary.py`,
     the same as in the workflow `release`, and so is the version of coverage.py
     (7.16.2).
   - `pre-commit run --all-files` is clean (also the job `pre-commit` of the CI); every
     `i18n/de.po` is complete.
   - Coverage: at least 95 % of lines and at least 95 % of branches in every module and
     in the project, 100 % of changed code (`codecov.yml`).
3. **Private check with real data** (never in this repository): the Papierkram exports
   of a real business are imported into a copy of its database and the result is
   compared with Papierkram (totals per year, open items, fixed assets). The protocol
   records the result without amounts.
4. **Data protection review before every push:** the working tree and every commit that
   the push publishes (`git log -p` of the range, not only the working tree) are scanned
   with the private list of real names, amounts, dates and document numbers; the
   protocol records the result (number of hits, never the list). Test data and the demo
   export (`_dev/werkzeuge/gen_demo_export.py`) are invented.
5. **Liability notice:** a lawyer or an independent expert reads the notice of the
   README; the feedback is worked in. Decision of the maintainer of 22.10.2026: the
   Alpha 19.0.1.0.0 is published with the notice reviewed by the maintainer only; the
   review is due before Beta.
6. **Tag:** an annotated tag `19.0.x.y.z` on the commit, created from a clean working
   tree. The workflow `release` runs the tests once more and attaches the test protocol
   (JUnit XML and coverage) to the GitHub release. Run `test_protocol.sh` again on the
   tagged commit: its `summary.md` must show the tag and a clean working tree, otherwise
   it is no release protocol. Started by hand for an existing tag (_Actions → release →
   Run workflow_, input `tag`), the workflow creates the protocol of that tag again with
   the tools of `19.0` and replaces the asset of the release.
7. **Archive:** both test protocols (GitHub release asset and local run) and the private
   results are kept by BM1 for five years.

The development status is _Alpha_ while the takeover has been run with the real data of
one business only; _Beta_ follows when takeovers of further businesses have been checked
against Papierkram.
